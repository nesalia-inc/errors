# Tasks: v1.4.x SEO Cleanup

## Overview

Concrete fixes captured during the SEO audit of `apps/web/`. Tasks are tracked
across GitHub Issues; this file is the in-repo index so the work stays visible
in the staging-first flow without needing to scrape the issue tracker.

- **[Implementation](./implementation/)** — None expected; all work is in
  `apps/web/src/app/` and `apps/web/src/lib/`.
- **GitHub Issues** — Each row links to the issue that captures scope,
  motivation, and risk.

## Audit source

The audit reviewed the SEO surface of `errors.deessejs.com`:

- `robots.ts`, `sitemap.ts`
- Per-page metadata in `(home)/page.tsx`, `(home)/blog/page.tsx`,
  `(home)/blog/[slug]/page.tsx`, `docs/[[...slug]]/page.tsx`
- Open Graph / Twitter image generators in `opengraph-image.tsx`,
  `twitter-image.tsx`, `og/**/route.tsx`
- JSON-LD emitted from the root layout, home, blog post, and doc pages
- RSS feed at `(home)/blog/rss.xml/route.ts`
- LLM surfaces (`llms.txt`, `llms.mdx/`, `llms-full.txt/`) and `proxy.ts`

The findings are eight distinct fixes. To keep the PRs reviewable, they are
grouped into **five** GitHub issues by concern (one of which — brand/parent
attribution — was added after the initial audit).

## Task Dependencies

```
03 (JSON-LD bug fix)
   └── 04 (metadata parity — references the same JSON-LD mindset)
   └── 06 (parent-entity / brand attribution — reuses the JSON-LD scaffolding)
   └── 07 (snapshot tests — needs at least one of 01-06 merged to capture baselines)

01 (robots disallow)                                    ─── independent
02 (sitemap lastModified)                               ─── independent
04 (metadata parity)                                    ─── independent
05 (favicon)                                            ─── independent
07 (snapshot tests / safety net)                        ─── lands in parallel
```

Issues 01, 02, 04, 05, and 07 can ship in any order or in parallel; issue 03
should land first because it changes the JSON-LD output that issues 04 and 06
also touch. Issue 06 overlaps on JSON-LD shape — keep its `Organization`
edits consistent with the JSON-LD drift in 03 and 04 (also switching
`author` / `publisher` blocks). Issue 07 is the safety net for the batch;
landing it alongside issue 03 means subsequent PRs update snapshots as part
of their own diff, which keeps review noise down.
